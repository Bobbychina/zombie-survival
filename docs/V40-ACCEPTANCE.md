### 本轮抓出并修掉的真问题
1. **`bandit` 不在 legacy 丧尸表里**：拾荒者据点的"火并"整场降级成普通丧尸（正好被上一步加的"未知 id 降级"兜住，否则会直接哑火）。已在 `ZOMBIES` 里补一条 `bandit` 数据（人类敌人：更脆、会打枪、掉弹药），现在打出来就是拾荒者。
2. **情报点亮被迷雾重放抹掉**：`ensureSaveWorld` 每次都从 `visited` 重放迷雾，一次性的"点亮"下一帧就没了（表现为买完情报地图上仍然没有 🔑）。改成派生状态：存档只记 `world.intel=true`，碎片点与实验室的可见性每次重算。

4. **卖出列表里会出现正拿在手里的撬棍**：卖出会让人赤手空拳。现在身上装备的物品不可卖（列表过滤 + 函数内二次校验）。

- **P3**：路上随机遇到幸存者（非营地）还没做——营地/据点是固定点位。列在下一轮候选。

## 十五、M15：地图生成改成"土地利用分区" + 多结局（8 个）

### 起因（用户要求）
> 全面优化地图生成逻辑，改成更加现实更加真实的模拟（比如工业区扎堆居民房扎堆）
> 然后搞多结局

老生成器是"四个独立噪声各自过阈值"，结果是**工业格与农田格随机交错**——地图像补丁，不像城市（`docs/_m15_mapdump.md` 里能看到 M15 之前那张图：工业是十几处 1~3 格的小疙瘩）。真实城市的形态来自几条简单规律：离市中心越远密度越低、同用途连片、工业沿交通线扎堆、商业长在核心与街角。

### A. 地图生成（`src/v4/worldgen.ts` 重写地形层）
| 机制 | 做法 |
| --- | --- |
| **城市强度场** | `urban = 低频噪声×0.7 + 区域偏置 − 距离衰减`（6 格内不掉、11 格后掉得更快）→ 内城连片、外围自然稀疏 |
| **土地利用分区** | 按真实优先级分 zone：水 > 高地林地 > 军事管制区 > **工业园（贴着城市边缘的一圈 −0.20<urban<0.16）** > **市中心（离中心 ≤2 格，带一个次级商业节点）** > 居民区 > 城郊 > 农田 > 林地 > 废墟 |
| **区域主题参与生成** | `regions-core.biomeBias` 从"只用于文案"变成真正的偏置：东郊真的是农田（21%）、西山真的是林地（39%）、江北真的是厂房带（10%，是山区的 12 倍）、滨海/南港真的是水域（24%） |
| **元胞自动机平滑** | 8 邻域多数票（≥5/8）跑 3 轮 → 孤立格被周围吸收；**再合并 <6 格的连通块**（真实城市不会有一座孤零零的工厂） |
| **两级路网** | 主干道/环线/家→实验室公路/军营公路 = 整格 `highway`；市内街道 = `road` 标记（格子还是居民区，但"沿街"）。修掉了老版"27% 的地都是高速"的假地形；车在公路上 0.55×、沿街 0.8×、越野 1× |
| **保底修复** | 每种 zone 有下限（cbd≥2、住宅≥5、工业≥3、农田≥3、林地≥3…），不够就按分数把最像的格子改过去——不会刷出"整张图只有工业"的废图 |
| **必有深水** | 若没有"离家 ≥6 格且四周全水"的格子，就在最合适处挖一个 3×3 的湖 → M7 的潜水点永远存在（这一步踩过坑：判定条件和放置条件不一致时，家门口的深水坑会骗过判定，结果一个潜水点都放不下） |
| **POI 按区分配** | 每个 zone 有偏好表（居民区=公寓/学校/超市/诊所，CBD=写字楼/商场/家电城，工业园=物流园/建材/木材厂/汽修厂，农田=农场/诊所/营地…）、**沿街权重 ×2.2**、**稀有建筑有上限**（医院≤2、军营=1、监狱=1）→ 像城市，而不是"随机撒 130 个点" |
| **地名** | 按 zone 起名：`铁西工业园 3 号厂区` / `柳河屯 4 号地` / `北岭林场 2 号林班` / `长春大道 1 号街区` |
| **UI** | 格子悬停显示用途（`商业中心 · 市区 · 危险 5 · 写字楼`）、主干道描边、沿街角标 |

## 十八、M17：元地图重做（12×12 程序化生成 + 辐射危险梯度 + 地貌上色）

### 起因（用户要求 + 用户转来的一份外部评审）
> 1.大世界太小了（应该是比如 12^12 / 24^24 这种、用不同颜色标注地图不同区域的类型，类似于小区域的地图）

评审意见里最扎眼的是**地理逻辑自相矛盾**与**危险度不成梯度**：
- "跨江"区在北边、"江北"区在南边；一条江横穿三行；老城被扔在角落；"东郊"紧贴市中心——九个地名是手写的，谁也没跟坐标对过；
- 出门往东是危险 2、往南直接危险 5，玩家学不到"越远越危险"这种地图直觉；
- UI 上：主城（余烬）没有危险标注、图标太写实、格子看不出"这地方能弄到什么"、顶部文案与选中区域不联动。

### 做了什么
- **元地图从写死的 3×3 改成按种子程序化生成的 12×12 = 144 个区域**（`regions-core.ts` 重写）：每个区域内部仍是一张 24×24 的格子图，所以世界总量 = 144 × 576 格。
- **区域类型**（9 种，与局部地图同一套地表词汇）：城市核心 / 居民区 / 城郊 / 工业区 / 军事管制 / 农田 / 林地山区 / 废墟 / 水域港区；类型决定**底色、生成主题偏置、资源标签、描述文案**。
- **地理大势**：主城固定生成在正中两格内；**海岸占满一整侧**（东或南，由种子定）、**山区/军管占对角的一角**；主城 1 圈内只可能是居民/城郊/核心，城市核心不会出现在外圈。
- **危险度 = 离主城的距离辐射递增**（按该种子下的最远距离归一化，铺满 1~5 档），再叠地形加成（军事 +1、远处的水域/工业区 +1）：中心=安全区、1 圈内 ≤2、四角 = 5。
- **地名按"方位 + 地貌"生成**（北岭山区 / 南港区 / 西工业区…），重名自动加"2 号"，不再是"区域 7"。
- **跨区改成多跳**：`regionPath` BFS 最短路（水面不能当过路通道，但**能开到堤岸上当终点**——否则整条海岸线的资源与第 5 章「到访水域」永远做不完），一格 2 行动力/2 油（斜向 3/3），一次最多 4 格（`MAX_HOPS`），太远就写"先开到中途的区域落脚"。
- **剧情/委托不再写死区名**：新增 `rtype:<类型>` 判定（"到访任意一处工业区"），跨区委托按类型挑目标，且**只挑一趟开得到的**（≤4 格；实测过"接了却永远开不到"的坑）。
- **UI 重做（这一版的视觉重点）**：
  - 12×12 色块网格：**底色 = 地貌**（9 色）、**底边条 = 危险度**（绿→黄→红五档）、**右上角数字 = 危险度**、格内 2~3 字缩写地名；
  - **余烬（主城）发光描边**、当前所在白描边 📍、没去过的格子压暗（地貌与危险仍看得见）、选中格描边 + **整条行车路线点亮**；
  - **点一格先选中**（不动身）→ 下方详情联动显示：地名 / 地貌 / 危险度 / 离余烬几格 / 到访状态 / 描述 / **"这儿能弄到"资源标签** / 行程报价（`🧭 开过去 N 格 · ⚡x · ⛽y` + 途经逐段列出 + 「出发」按钮）或**拦截原因 + 怎么办**；
  - 两条图例（9 种地貌 / 5 档危险各一行），面板顶部写"当前在 X · 类型 · 危险度 · 已到过 N/144"。

### 探针/实现抓到并修掉的真 bug

## 十九、M17.1：给元地图拴上缰绳（用户转来的第二份评审）

### 起因（用户原话 + 截图）
> 好诡异
> 这张图简直是"人工智障"的教科书级灾难现场……**命名系统**：方位词+固定词库穷举，「北西废」听着像在骂人；**空间布局**：上一秒居民区、下一秒工业废墟，中间连个绿化带都没有，"这是把大富翁的棋盘放进搅拌机里打碎了再倒出来"；**难度曲线**：身处市中心，四面八方紧挨着危险度 2、3 甚至更高，"没有新手村，出生即 Boss 战"；**色彩**：色块像马赛克一样交织；建议：**加一点点约束规则（Constraints）**。

读图核对（我用视觉通道把截图逐字读了一遍）后：**四条里有三条成立，一条是误读**——
- ✅ 命名确实是"方位 + 词库穷举"，而且 `short` 取的是**全名前 3 个字**，于是截出了「北西废」「北西日」这种半截词；
- ✅ 布局确实是"每格独立摇号"：类型只按距离分档，档内纯随机，所以工业区会贴着市中心、农田散在城里；
- ✅ 色彩/色块：九种颜色都挤在同一个暗灰区间（`#3a4250` 和 `#3b4152` 肉眼几乎分不出），加上马赛克式排布，看着就是一团噪点；
- ❌ "危险度完全没有梯度"不成立：主城是危险 1、四角是 5，环平均值单调递增（截图里"余烬=2"是把邻格的数字读串了）。但"出门就是危险 2"是真的——第一版只把主城那一格设成安全区，紧邻一圈全是 2，确实没有"新手村"。

### 做了什么（`regions-core.ts` 的生成器重写 + 命名/配色重做）
1. **分区生成**（换成和 24×24 局部地图同一套思路）：绕主城取连续噪声扰动"分带边界"（城市不是同心圆，是不规则团块）→ 带内按**同一张平滑噪声场**排序切片分类型（空间连续 ⇒ 同类自然成片）→ 1 轮保守元胞平滑（≥6/8 邻居才改）→ **合并 <3 格的碎块**（并进接壤边界最长的邻居）。
2. **硬约束（评审要的"缰绳"）**：工业区不与城市核心相邻；城市核心只在 2 圈内且**只有一片连通 CBD**（其余降级成居民区）；农田/林地不进 2 圈；军管区只在山地那一角且 ≤6 格；海岸仍占满一整侧（第二列允许有湾，但水不会"扩散"进内陆）。
3. **类型保底/封顶**（这条是踩出来的）：合并碎块时给每种类型设下限与上限——第一版没有下限，废墟被并到 0 格，而第 5 章的目标正好是「到访一处废墟」，**主线直接死锁**；没有上限则居民区会把全图吃掉（144 格里 56 格）。现在九种类型都保底存在（工业/水域/废墟 ≥5 格）。
4. **地名**：短名单独维护词表（每种类型 8 个 2 字地貌词），显示成"1 字方位 + 2 字地貌"（北化工 / 西粮仓 / 东码头），并按"当前用得最少"挑词 → 144 格里 100+ 个不重样；全名仍是"方位 + 长地貌词"，重名自动加" N 号"。**「北西废」这类半截词从数据层就没有了**。
5. **配色**：九种类型换成能区分的色相（城市核心 `#55607f` / 居民 `#3f4a63` / 城郊 `#38564c` / 工业 `#6b4a2c` / 军管 `#6d3336` / 农田 `#6d6a2e` / 林地 `#2f5a36` / 水域 `#1f4a76` / 废墟 `#5b4a5e`），局部地图的 `b-*` 地表色同步改成同一套。

8. 顺带修：**海岸有湾之后，深处的港区一度"开车过不去"** → 水域目的地允许沿海岸贴水走一段（去陆地的路线仍然绝不穿水）。

## 二十、M17.2：第三份评审（"AI 被电击治疗三个疗程后勉强出院"）

### 起因（用户转来的第三份锐评，进步分 4/10）

## 二十一、M18：小地图"全黑走不动"的线上 bug + 区域事件

### 起因
- **用户报的 bug**：「小地图的安全屋周围怎么没有点亮的地方了，这让玩家没法移动」
- **评审 #4 的建议**：「既然地图区块做好了，可以在里面填上随机事件。比如"西工业区"有概率触发毒气泄漏、"北军管"有概率捡到高级武器，让死板的网格活起来。」

### A. 全黑 bug：根因与修复（`worldstate.ts`）
**根因**：M17.1 的"地图重画迁移"按版本号清空 `visited`（按坐标存的地形进度必须作废），但**没有把玩家脚下那一格重新标成"去过"**。而迷雾是每次加载都从 `visited` 重放的（`revealed` 全部先清零再按 `visited` 点亮），所以迁移完之后：整张图 576 格全黑 → 本地地图只能点"已点亮"的格子 → **玩家一步都动不了**。

**修复**：把"脚下必亮"做成**不变量**，三处兜底（任何一条单独成立都不会再卡死）：
1. `ensureSaveWorld` 校正完 `cur` 之后，无条件补一次 `visited[脚下] = 1`；
2. 迷雾重放结束后，再检查一次"脚下是否 revealed"，不是就补点（连周围 3×3 一起亮）；
3. 跨区落地（`switchRegion`）本来就会 `markVisited`，保持不变。

**为什么这样修**：`visited` 是唯一真相源，只要"人在哪、哪就亮"，无论存档是被迁移清空、被写坏、还是从别处导入的，玩家都永远有一个可点的起点。

**实测证据**：
- 单测 **232/232**，其中新增/改写 3 条：迁移后"`visited` 只剩脚下那一格"、"脚下与周围至少 6 格是亮的"、"`visited` 被清空的坏档打开后依然亮"；
- 浏览器探针 `docs/_m18_fog_event_probe.mjs` **11/11**：
  - 新档：**9 格点亮 / 9 格可点**（安全屋 + 一圈），点相邻格真的走过去（`(12,12) → (13,12)`，行动力 9→8）；
  - **坏档复现**：把 `visited` 清空 + 版本号改成 999 → 重载后依然 **9 格点亮 / 9 格可点**，并弹出"地图生成器更新了"的迁移说明；
- 视觉复核（`docs/_m18_shots/m18-local-grid.png`，只截地图网格）："中央偏下有一块 3×3 点亮的区域，中心格带橙色房屋图标（安全屋），其余为未点亮的暗格"。

### B. 区域事件（M18，`region-events-core.ts` + `region-events.ts`）
按评审建议做的"让网格活起来"，但**约束成一条可预期的规则**而不是纯随机：
- **按地貌给事件**：工业区=毒气泄漏/管道爆燃/夜班仓库/机修间；军管区=军械箱/巡逻无人机/雷区边线/防化柜；农田=野猪群/粮囤/老井；林地=狼群/伐木营地/山体滑坡/药圃；水域=涨潮/渔获/搁浅驳船；废墟=楼板塌陷/拾荒者陷阱/旧保险柜；居民区/城郊/城市核心各有 4 条。**9 类 × 4 条 = 36 条**，文案都带末日味道。
- **概率随危险度上升**（`eventChance = 0.18 + tier×0.09`，封顶 0.75），并且**危险区更容易抽到 hazard**（`hazardBias` 同向）；**安全区（危险 1）永远不掉血**——那是新手村。
- **触发点**：① 跨区落地时掷一次（主城不掷，安全屋是唯一绝对安全的地方）；② 换日时人在外面再掷一次。
- **结算落地**：血/行动力/材料走 clamp（不会打到 0 血直接死，材料不为负），物品走 `L.grant` 统一入口，日志写成人话（`📌 西工业区 · 毒气泄漏：…（生命 -14）`），并进"现场日志"的 trail。
- **可预期**：区域详情面板多一行「这一带的状况：毒气泄漏 / 管道爆燃 / 夜班仓库」——出发前就知道自己要去冒什么险，地貌分区因此不只是颜色。
- **可测试**：纯函数（同样随机序列 → 同样事件）+ `auditRegionEvents(已知物品表)` 自检（物品 id 必须真实存在、数量必须给、不能回血、一次掉血 ≤25、材料 |Δ| ≤20、行动力 |Δ| ≤3）。

**实测证据**：
- 单测 **9 条**（内容完整性、id 唯一、概率单调、掷骰可预测、安全区不掉血、hazard 占比随 tier 上升、详情文案、地貌对应关系、事件池覆盖真实地图上的每种类型）；
- 探针：按当前区域类型抽到对应事件（`core → 超市残货`）、日志出现 `📌 …`、`V4World.regionEvent()` 可查、详情面板出现「这一带的状况：毒气泄漏…」；
- 回归全绿：M12 15/15、M14 27/27、M15 11/11、M15.1 8/8（两条断言按"脚下常亮"更新）、M16 11/11、M17 31/31。

### 已知问题
- **P2**：区域事件目前只走日志，没有专门的弹窗/图鉴；同一类事件的文案是固定的（没有"第 N 次遇到"的变体）。

## 二十二、M19：局部地图"越深越难" + 建筑分布（用户的 idea）

### 起因（用户原话）
> 我有一个 idea：地形生成你不如接一个柏林噪声——对于难度来说越深的地方难度越高，对于建筑分布我没啥好的思路你看着办

**先说一句实话**：噪声早就接了（M15 起地形就是 simplex 噪声：海拔 + 城市强度 + 工业 + 商业 + 乡村五张场，再跑分区规则与元胞平滑），
所以这条 idea 里真正没做的是**"越深越难"**——旧的危险度写的是"1 + 离**市中心**的距离/3 + 各种 zone 加成"，
后果有两条：① 危险度跟"离家多远"没关系（家边上就可能是 CBD，危险度 3）；② zone 交界会跳台阶（CBD +2 紧挨郊区 +0）。
建筑分布那条用户让我自己定，我定了"**深度偏置**"：日用品靠家、硬货在深处——这样深度不只是难度，也是收益。

### 做了什么（`src/v4/worldgen.ts`）
1. **危险度 = 深度场**：基准按"离**安全屋**的切比雪夫距离"归一化铺满 1~5（家与紧邻一圈 = 1，最外圈 = 5），
   再叠一张低频噪声做 ±1 的局部扰动（只加在中段，最外两圈保持一整片红、家门口那圈不动），
   最后跑**两侧梯度钳制**（每格必须落在邻居的 ±1 内）+ 第二圈封顶 2 的不变量循环
   → "越深越难"能**一路走过去**，不会出现"危险 5 挨着危险 3"的墙。
2. **建筑密度 = 噪声成片 × 距离衰减 × 沿街加成**：老写法只有 zone 基数 + 沿街，
   于是"城郊"和"市中心"的建筑密度几乎一样（图上到处是房子）；现在低频密度噪声决定"哪里有房子"，
   距离衰减决定"越往外越稀"，沿街仍然更容易出店铺（真实城市的样子）。
3. **深度偏置（用户让我定的部分）**：军械/监狱/大型商超/物流园/水厂/电台/前哨这些**硬货随深度加权**（最深 ×2.6），
   超市/药房/加油站/汽修/医院这些**日用品随近度加权**（家门口 ×1.4）；
   修车点与补给点的保底仍然强制（主线与载具都靠它们）。
4. **本地地图也能切"危险度上色"图层**（复用 M17.2 的图层开关，`localStorage.dsh.regionlayer`）：
   地貌色看"这是什么地形"，危险度图层看"该往哪跑"，图例跟着换。

### 实测证据
- **单测 241/241**（新增 9 条 M19）：
  - 家的 3×3 恒为 1；相邻差 ≤1（全图扫描）；最外圈平均 ≥4.5；1~5 都出现过；水域不在安全圈内时 ≥2；
  - 日用品 vs 硬货的平均离家距离：硬货更远（跨 3 个种子统计）；
  - 家附近 8 格内必有补给点、11 格内必有修车点；建筑不压水/不压公路（沉没基地除外，它本来就该在水下）；
  - 建筑成片：6×6 个 4×4 窗口里既有 ≥4 个建筑的忙碌街区、也有 ≥4 个空地窗口。
- **读图产物** `docs/_m19_mapdump.md`：3 个种子的危险度网格 + 建筑分布（自己读了一遍，
  中心是 1~2 的绿心，最外两圈是整齐的 5，工业与军事 POI 落在中深处）。
- **浏览器探针 `docs/_m19_depth_probe.mjs`：10/10 通过**（本地 + 线上）：
  - 本地地图有"危险度上色"图层，576 格全部带危险度，图层只用 5 种梯度色；
  - 家的 3×3 = 1；**全图相邻差最大 1**（实测最大差=1）；

## 二十三、M20：世界管理 / 种子分享 / 幽灵据点（异步 PVP）/ 开发者回传

### 起因（用户 idea，四条）
> ① 异步联机（PVP 掠夺）：把自己的"安全屋仓库数据"上传到公共 Gist 或 JSONBin，别人探索时有几率刷出"幽灵据点"，打赢抢走部分材料。
> ② MC/泰拉瑞亚式的种子分享：导出种子 + 初始状态发给朋友"来挑战我这张开局"。
> ③ 可以创建新的世界：像 MC/泰拉那样世界化管理，自动同步云存档。
> ④ 开发者回传（匿名统计）：玩家许可下，死亡时把死因/存活天数/区块**匿名**发到统计端点，用来调地图生成。

四条都做了，但**联网的那一步都停在"玩家自己按复制"**——理由写在 D 里，这很重要。

### A. 挑战码 / 种子分享（`share-core.ts`）
- 世界 = 种子 + 开局预设（标准 / 清贫 / 地狱：起手材料 12 / 4 / 0）；种子本来就决定整张 12×12 元地图与每张 24×24 局部图。
- 码形如 `ZS1-<base64url>-<校验和>`：**纯字符串**，发微信/贴吧都行，也支持 `?challenge=` 链接直接进游戏。
- 解析严格：校验和不对 / 版本不认识 / 种子非法一律拒绝并给人话原因，绝不"半信半疑地开局"。
- 面板一键复制；粘贴别人的码 → 立刻多出一个同种子的世界并切过去。

### B. 多世界管理（`worlds-core.ts` + `worlds-ui.ts`）
- 注册表 `zsv_worlds_v1`：`{ activeId, worlds[{id,name,seed,preset,day,deaths,lastPlayed,note}] }`，面板里能建/进入/改名/删除（至少留一个）。
- **当前世界的存档仍然写在老地方**（`zombie_survival_save_v2`）：切换世界时把当前存档挪到 `zsv_save_<id>`、把目标世界的搬回主键。
  这样指纹校验、自动存档、云同步、导入导出这些既有链路**一行都没改**，云同步天然就是"同步当前世界"。
- 老玩家第一次进来：没有注册表 → 用现有存档的 seed 自动认领成第 1 个世界（不丢档、不弹窗）。

### C. 幽灵据点 · 异步 PVP（`ghosts-core.ts` + `ghosts.ts`）
- 把自己仓库压成 `ZG1-…` **幽灵码**（材料、压箱底的那件东西、威胁度、天数、一句挑衅）；朋友粘进去 → 他地图上多一个 👻 格。
- 落点 = 哈希(幽灵码 + 世界种子)：同一张图位置固定、不同玩家的图位置不同；**偏好点压在公路/水面上时自动往外找一格**
  （踩过的坑：第一版直接放弃 → 玩家"导入成功但地图上是空的"，静默失败）。
- 踩上去就是守卫战（威胁 1~5 → 3~10 只混编，威胁 5 带一个暴君），赢了结算：抢走对方快照的 **35%（3~60 材料）+ 一件压箱底物品**，标记已清。
- **抢的是快照副本，上传者本人的存档一点都不少**——UI 与日志都明说了（不然玩家会以为被偷了）。
- **公共池（Gist / JSONBin 自动上传 + 拉取）没做**，留到下一轮：需要账号绑定 + 明确的同意开关，
  而且"往公共池写别人能读到的东西"值得单独确认一次。

### D. 开发者回传（`telemetry-core.ts`）——为什么不做成"自动上传"
- 用户原话是"在玩家的许可下……匿名发到某个统计端点"。这游戏是**纯静态页**：没有我控制的服务器（GitHub Pages 只发文件），
  而"自动联网上报"是必须在 UI 上明确同意、且要能关掉的行为——**不能靠一句注释糊过去**。
- 所以做成**本机台账 + 一键导出**：死亡/结局自动记一条（天数、死因、区域 id 与类型、危险度、击杀与材料、天级时间戳），
  面板直接出结论（"最容易吃人的是「工业区」（N 次，平均第 X 天）；最常见的死因是…"）+ 最难/最易清单。
- 导出是**匿名化 JSON**（击杀与材料按 10 分桶、时间到天、无账号/存档/设备字段）；开发者可用"合并别人的统计"把多份台账并进本地看。
- 想要真正的自动上报，只需把 `exportLedger()` 的结果 POST 到端点即可——**接口已就绪，缺的是"谁收"**。

### 已知问题
- **P1（隐私向）**：幽灵码里的仓库快照是明文 base64（无加密、**无签名**）——玩家可以改自己的码把自己写成 9999 材料。

- **P2**：幽灵码靠手动粘贴传播（没有公共池）；Gist/JSONBin 的自动上传/拉取要先做账号绑定 + 同意开关。

## 二十四、M21：修掉"动不了"的死锁 + 探索页改成卡片墙（用户两张截图）

### A. "这样动不了啊"（图 1）——根因是**世界实例被挤掉 + 迷雾重放被跳过**

- 截图事实：整张本地地图 576 格全是迷雾 `?`，只有安全屋那一格亮着（🟡 边框），**一格都点不了**。
- 复现路径（真实玩家会走到的）：
  1. `quests.poisIn()` 为了判断"别的区域有没有某种 POI"会调 `worldOf(seed, 别的区域)`；
  2. 旧实现的世界缓存**只有 1 个槽位** → 当前区域的世界对象被挤掉，连它身上已经点亮的 9 格一起没了；
  3. 下一次 `ensureSaveWorld()` 拿到的是**刚刚重建、全黑**的新实例；
  4. 而 C11 的性能优化"指纹（visited 条数/情报/无线电/区域）没变就不重放迷雾"**照旧跳过重放** →
     整张图连脚下都是黑的。而移动的唯一入口是"点一个已点亮的邻格"，于是**永久死锁**。
     （只有同时满足"指纹已写过 + 实例被换掉"才会中招，所以它藏了两轮迭代才被玩家撞上。）
- 修法（`src/v4/worldstate.ts`）：
  - 世界缓存从单槽改成 **8 槽 LRU**（`worldOf` 里最近用过的排到队尾、溢出丢最旧）；
  - 迷雾指纹里加上**世界实例本身**（`lastSynced.w === w`）：实例换了就一定重放，跟缓存策略解耦；
  - 把"脚下必亮"抽成 `hereLit()`，**快路径（指纹命中）也跑一次自检**——代价是一次字典查找，
    收益是"玩家唯一行动入口"这条不变量再也不可能被优化吃掉。
- 证据：`tests/fog-invariant.test.ts` 两条（改动前 **2/2 红**：`expected 1 to be 9` 就是那张全黑图；改动后绿）；
  浏览器探针里用 `DEV.scanRegion()` 走**真实**的 `quests.poisIn` 路径，然后断言"脚下仍亮 + lit=9 + 还能走一格"。

## 二十七、M23：账号 = GitHub（设备码 + 令牌码两条登录路，UI 上取消注册）

- 用户原话：**"再搞一个更方便的，设备码（就这两个），然后优化一下注册登录逻辑——只能用 github 账户登录不能注册"**。
- 改法（`src/account/account.js` + `src/v4/account-ui.ts` + `src/main.ts`）：
  - **库里新增"GitHub 即账号"**：`signInGitHub(token)` = 校验令牌 → 找同 login 的记录（老账号绑过 GitHub 就复用，进度与存档槽跟着走）
    → 找不到就建一条 `uid = gh-<login>` 的**无口令**本机账号 → 写会话 → 绑定 provider。`signInGitHubDevice(onCode)` 走同一条设备码流程，
    只是把"拿到令牌之后干什么"换成登录（`bindGitHubDevice` 保留原来的绑定语义，两者共用新抽出的 `githubDeviceFlow()`）。
  - **令牌记住了**：以前本机模式的令牌只放 `sessionStorage`（关标签页就失效，每次都要重绑），现在另记一份在
    `localStorage`（`dsh.ghtok.keep.v1`），`_cloudToken` 兜底读它，`unbind` 会清掉——这才叫"更方便"。
    同时新增 `rememberedGitHub()` / `signInGitHubRemembered()`：登录页会给一颗「⚡ 用这台设备记住的 GitHub 直接进」。
  - **UI 上取消注册**：登录页只剩两条路（📱 设备码登录 / 🔑 令牌码登录）＋一行小字「旧账号（密码）」；
    `V4Account.doRegister` 与注册用的邮箱输入框全删。GitHub 账号的面板不再显示「改密码」「恢复码」
    （那是有密码账号的事），头像行显示「GitHub 账号（没有密码）· GitHub @login」。
  - 老账号不受影响：密码登录与恢复码找回都还在（入口收进 `legacyLogin()` 的弹窗），`account.js` 的
    `register/login/recover` 一行没动（游戏厅页面继续用）。
- 文档：README 功能行 + 「为什么登录是设备码/令牌码这两条？」整节重写；PRIVACY.md 第 3 节改成
  「登录与云存档用的 GitHub 令牌」（两条登录路对照表 + 令牌存在哪，含新的 localStorage 键）。
- 实测：`docs/_m23_github_login_probe.mjs` **本地 18/18**、**线上 18/18**：
  - `V4Account.doRegister` 已不存在；登录页只有设备码/令牌码两条路，没有任何注册按钮或邮箱输入框；
  - 老账号弹窗只有用户名/密码 + 登录（+ 恢复码找回），同样没有注册；
  - 令牌弹窗标题变为「用令牌码登录」、按钮「登录并启用云存档」，权限披露与"不想给令牌"的退路仍在；
  - **线上设备码真的出码**（`clientId = Ov23liPzQ…` + 中继都活着，探针断言 9 位码格式）——本地无 auth-config 时给出可读错误；
  - 注入一条 `gh-` 账号后：面板认「GitHub 账号（没有密码）」、给 `GitHub @login ✕` 解绑、不显示改密码/恢复码；
    退出登录后登录页出现「⚡ 用这台设备记住的 GitHub 直接进」。
- 已知问题：
  - **P2**：云后端（Worker）模式下 GitHub-only 登录没做——那种模式下账号由服务端持有，仍然要求先用口令登录；
    本游戏线上实际跑的是本机模式（`api` 配了但后端不可达时会自动退回），所以不影响玩家。

## 三十、M24：五张截图五个问题（卡片空白 / 图层混色 / 重复与空白 / 技能没用 / 溢出）

### 1. "为什么卡片中间有空白"
- 根因：卡片墙用的是**行对齐网格**（`grid-template-columns:auto-fill`），同一行的高度由最高那张卡决定，
  矮卡下面就是空白。实测 @2048 宽：水体 232px 旁边的菜园只有 65px → 空 167px；今日行动 141 旁边的格子详情 84 → 空 57px。

  实测列内最大间隙 167px → **12px**（就是卡片间距本身）。

### 2. "为什么地貌上色还有危险度，直接把地名和危险度删掉"

### 1. "为什么整个页面还能滚动"（根因是一个 33px 的 BETA 条）

- 用户原话只有这一句 + 一张 2047×1105 的探索页截图。**先在用户视口复现再动手**：

- 根因：站点 BETA 声明条 `#beta-notice` 是 `body` 里的**流内 sticky** 节点（实测 33px），
  而 `#app` 写死 `height:100vh` 且从那条下面开始 → 文档比视口正好高 33px。
  `body{overflow:hidden}` 挡不住这件事：**滚动溢出会从 body 传播到 html/视口**，所以整页能滚。
  同一次测量还暴露第二个问题：`#view` 的网格行是 `32px 902px（地图）+ 588px（卡片）`，
  903px 的容器塞 1522px 内容 → 地图底边（1195）越过容器底（1105），"下沿被切"是必然的。
- 修复（`src/styles/game.css` + `src/styles/v4.css`）：
  - `#app{height:calc(100vh - var(--beta-h,0px))}`，并用 `:has()` 认这两条站点横幅：

  - ≥1700px（地图与卡片同屏）改成 `grid-template-rows:auto minmax(0,1fr)`，
